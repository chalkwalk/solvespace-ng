# M1c Panels Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Written 2026-10-16
> while the owner was away ("continue going forward"); the design calls below are rulings for
> the owner to review. Tasks 1–9 add the new panels next to the old property browser, which

**Status (2026-10-16):** tasks 1–9 done on `ng/m1c-panels` (task 1 folded into task 2);
task 10 waits for the owner. The parity list is `docs/m1-parity.md`.

**Goal:** Every text-window screen and every command has a home in the new UI: an Outliner, a
Properties panel that follows the selection, a Problems panel, and panels for preferences,
styles and the view, so the property browser and the old frontends can go.

**Architecture:** Each panel is split in two, like `StatusModel` in M1b:
- a **model** in `src/ui/<panel>model.{h,cpp}`: plain structs built from `SK`/`SS`, plus the
  actions it offers as core methods (`Group`, `GraphicsWindow`, `SolveSpaceUI`), unit-tested
  in `test/ng/`;
- a **view** in `src/ui/<panel>.cpp`: ImGui drawing only, tested end to end with the UI harness
  in `test/ngui/` (click, type, check the model).
Text-window handlers whose effect the panels need move into core methods first (one screen per
commit, AGENTS.md §9), and the old handler calls the new method, so both UIs stay in step.

**Tech stack:** C++20, Dear ImGui 1.92.9b, the M1 harness (`Platform::Driver`).

**Spec:** `AGENTS.md` §5 (layout, panels), §8 (M1 done-when: parity checklist), and the M1
roadmap at the end of `2026-10-15-m1a-sdl-imgui-shell.md`.

## Global Constraints

- The old property browser keeps working until Task 10; no screen is removed before its
  replacement passes its UI tests.
- Every panel action is runnable headlessly (a core method or a registered command).
- Every field that takes a number accepts an expression in display units (`Expr`), as the
  property browser does.
- Panels float over the viewport (AGENTS.md §5); positions, sizes, collapsed and shown state
  persist through `Platform::Settings` (`NG_Panel_<name>_*`).
- C++20; GPLv3 for files derived from SolveSpace; no new dependencies except lunasvg (allowed
  in §2) when the icon task comes.

## Rulings (design calls the owner has not made yet)

1. Keys (Modern preset): `N` toggles Properties (it toggled the old browser; the old browser
   stays in View ▸ Show Property Browser), `O` toggles the Outliner, `Shift+P` toggles
   Problems. Classic gets no new keys; all three are in the palette.
2. Outliner rows: active radio, eye (visibility), status badge (`ok`, DOF count, `ERR`, `!`
   for a contour/boolean warning), name. Click = select the group (Properties shows it);
   double-click or the radio = activate; badge click = Problems for that group; right-click =
   Rename / Delete / Isolate. Groups after the active one are dimmed, as the browser does.
3. Properties shows, in order: the selection (entities, constraints, with an editable value for
   a dimension) if anything is selected, else the group chosen in the Outliner, else the active
   group.
4. Problems lists, per group: failed solves (with the culprit constraints, click to select),
   redundant constraints, contour problems (not closed, not coplanar, self-intersecting) and
   boolean failures. It opens itself when a new problem appears; `Shift+P` hides it.
5. Preferences (`configuration`), Styles (`line styles`), View (`view`), Paste Transformed,
   Step Dimension and Tangent Arc each become a panel opened by their command or palette entry.

## Review Focus

1. Editing a field while the solver is mid-drag or a modal tool is active must not corrupt
   undo: every edit is one undo step, made through the same core method the browser used.
2. Deleting the group shown in Properties, or reloading the file, must not leave a dangling
   handle in any panel model.
3. Expressions: `2*pi`, `1/3`, units (`mm`, `in`) and invalid input; invalid input keeps the old
   value and says why.
4. Very long lists (hundreds of groups or constraints) stay usable: clipped lists, no per-frame
   O(n²) work.
5. Keyboard: typing into a panel field must never trigger keymap commands (the router's
   text-capture rule), and Esc leaves the field before it cancels a tool.

### Task 1: Panel framework
`src/ui/panels.{h,cpp}`: `Panel` (name, title, default dock edge, shown flag, settings
persistence), `BeginPanel/EndPanel` wrappers with the theme, `ui.toggle-outliner`,
`ui.toggle-properties`, `ui.toggle-problems` actions and keys (ruling 1).
Tests: `test/ngui/panels` — toggle by key, position persists across a restart of the main
window, typing in a panel field does not run commands.

### Task 2: Outliner
Model `OutlinerModel BuildOutliner()` (rows from `SK.groupOrder`) and the panel (ruling 2).
Core: `Group::Rename`, `GraphicsWindow::DeleteGroup`, reuse `ActivateGroup` and visibility.
Tests: model unit tests; UI tests for select, activate, eye, rename, delete, isolate.

### Task 3: Properties — group
Port `ShowGroupInfo`: name, type line, solid-model combine, repeat count, link file and scale,
helix pitch, colour and opacity, the option checkboxes, the request and constraint lists
(click selects). Core setters for every `ScreenChangeGroupOption` effect.

### Task 4: Properties — selection
Port `DescribeSelection` and the constraint screens: entity and constraint descriptions,
editable dimension value (expression), reference / show-as-radius toggles, TTF text, font and
kerning.

### Task 5: Problems
Model from `Group::solved`, `polyError` and boolean results; panel per ruling 4; clicking a
problem selects and highlights its culprits.

### Task 6: Preferences
Port `ShowConfiguration` (every `ScreenChange*` setting) to a Preferences panel, grouped
(Display, Export, Solver, Navigation, Autosave), plus the NG settings (theme, keymap preset).

### Task 7: Styles
Port `ShowListOfStyles` and `ShowStyleInfo`: list, create, delete, assign to selection, and
every style property.

### Task 8: View, Paste Transformed, Step Dimension, Tangent Arc
Port `ShowEditView`, `ShowPasteTransformed`, `ShowStepDimension`, `ShowTangentArc`.

### Task 9: Parity checklist
`test/ng/parity`: a table maps every `GraphicsWindow::MenuCommands()` entry and every
`TextWindow::Screen` to its new home (palette, pie, panel, key); the test fails for anything
unmapped or mapped to a home that does not exist. `docs/m1-parity.md` is generated from it.

### Task 10 (owner's go-ahead required): Remove the old frontends
Delete `guigtk.cpp`, `guiwin.cpp`, `guimac.mm`, `guiqt.*`, their CMake branches, the floating
property-browser FBO panel and `src/toolbar.cpp`; keep the HTML/web frontend.
