# M2 Kernel Seam and Background Regeneration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (chosen: inline;
> the owner asked for work to continue through the roadmap without intervention, 2026-10-21).

**Goal:** `IKernel` + `SolveSpaceKernel` behind `Group::GenerateShellAndMesh()`, then solids
regenerated on a worker thread while dragging, with the stale solid drawn as a ghost
(AGENTS.md section 6, milestone M2). Done when regression output is unchanged.

**Architecture:** Kernel operations take their inputs as values (a `KernelJob`: profile
loops, vectors, colour, the previous running body, the combine mode) and return a `Body`
(`SShell` + `SMesh` + `booleanFailed`). Naming faces goes through a `FaceNamer`: on the main
thread the group's own `Remap` (exactly today's calls, so the saved remap tables don't
change); on a worker a snapshot of the remap table and of the existing face entities, where a
miss sends that group back to the synchronous path. The chord tolerance is captured in the job
and read through a thread-local override; naked edges found by a worker are carried in the
result.

**Tech stack:** C++20, std::thread / std::mutex / std::condition_variable (no new deps).

**Spec:** AGENTS.md sections 4 (kernel/ layer, dependencies point down), 6 (IKernel,
SolveSpaceKernel, regeneration), 8 (M2 row; tests stay green on every commit).

## Global constraints
- The existing `test/` suite stays green on every commit; stock render/export references are
  never edited (regression output unchanged).
- `.slvs` output unchanged: remap tables and face handles exactly as before.
- `src/kernel/` must not reference `SS.GW`, `SS.TW` or `ui/`.
- Stock frontends keep building (build/ passes as well as build-ng/).
- Tests, export, save and the headless runner always regenerate synchronously.

## Review focus
1. A drag that adds a face (first extrusion of a new line): the snapshot misses; the group
   must regenerate synchronously, never with a face left unnamed.
2. Saving or exporting while a background job runs: the save must wait for the newest result.
3. Undo during a background job: the stale result must not be applied over the undone model.
4. Chord tolerance changing between passes (zoom during drag): the worker uses its captured
   value only.
5. A boolean failure found on the worker: naked edges and booleanFailed reach the UI as now.

### Task 1: FaceNamer

**Files:** `src/srf/surface.h` (declare), `src/srf/shell.cpp`, `src/groupmesh.cpp`,
`src/group.cpp`, `src/sketch.h`; test `test/kernel/facenamer/test.cpp`.
- `struct FaceNamer { virtual hEntity Name(hEntity in, int copy) = 0;
  virtual hEntity ExistingFace(hEntity in, int copy) = 0; bool missed = false; }`.
- `GroupFaceNamer` (main thread): `Name` = `group->Remap`; `ExistingFace` = Remap + the
  `SK.entity` check, as shell.cpp does now.
- `SnapshotFaceNamer`: copies of the group's handle, remap map and existing face handles;
  a miss sets `missed` and returns NO_ENTITY.
- `SShell::MakeFromRevolutionOf` / `MakeFromHelicalRevolutionOf` take `FaceNamer &` instead of
  `Group *`; the extrude annotation in groupmesh.cpp uses the namer.
- Tests: the snapshot resolves known keys to the same handles as `Remap`; an unknown key sets
  `missed`; the whole suite unchanged.

### Task 2: IKernel and SolveSpaceKernel

**Files:** create `src/kernel/kernel.h`, `src/kernel/solvespacekernel.cpp`; modify
`src/groupmesh.cpp`, `src/CMakeLists.txt`; tests `test/kernel/solvespace/test.cpp`.
- `Body { SShell shell; SMesh mesh; bool booleanFailed; }` with deep copy/clear helpers.
- `KernelJob` captures: op (NONE/EXTRUDE/LATHE/REVOLVE/HELIX/STEP_TRANSLATE/STEP_ROTATE/
  LINKED), loops (deep copy of the source group's `bezierLoops`), vectors and angles, colour,
  side-face lines (endpoints + entity handle) for extrude naming, step parameters, linked
  transform, `forcedToMesh`, `combine`, `mergeCoincident`, `suppress`, previous running body,
  chord tolerance.
- `IKernel::Run(const KernelJob &, FaceNamer &) -> KernelResult { Body thisBody, running;
  NakedEdges; }` and `IKernel::Supports(Op)` (fillet, chamfer, shell, loft, sweep: false for
  SolveSpaceKernel; the UI greys those out in M3).
- `Group::GenerateShellAndMesh()` = `BuildKernelJob()` + `Kernel().Run(job, GroupFaceNamer)`
  + `ApplyKernelResult()`; identical results.
- Tests: an extruded square's mesh volume; union of two overlapping boxes; `Supports(FILLET)`
  is false; the full suite unchanged (regression).

### Task 3: Background regeneration and ghost preview

**Files:** create `src/kernel/worker.{h,cpp}`; modify `src/generate.cpp`, `src/groupmesh.cpp`,
`src/solvespace.{h,cpp}`, `src/drawentity.cpp`/`groupmesh.cpp` (ghost draw),
`src/platform/guisdl.cpp` (poll results each frame); tests `test/kernel/worker/test.cpp`,
`test/ngui/regen/test.cpp`.
- `SS.backgroundRegen` (off by default; NG turns it on only while dragging or grabbing).
- In `GenerateAll`'s second pass, with backgroundRegen, the groups first..last are captured as
  one job chain (each group's job takes the previous result as its previous body) and handed
  to the worker; the newest chain replaces any queued one; a running chain finishes but its
  result is dropped if a newer chain was submitted (generation counter).
- Each frame the main thread applies a finished chain whose generation is current; a chain
  with a namer miss is regenerated synchronously instead.
- Until then the groups keep their previous bodies, drawn as a ghost (the mesh at 35% alpha,
  no edges) and `Group::regenPending` is set.
- `SS.FlushRegeneration()`: wait for the worker and apply; called before save, export, undo
  snapshots, and when the drag ends (mouse up / grab confirm), so the model is exact after.
- Tests (headless): a chain run on the worker equals the synchronous result (surface and
  triangle counts, volume); a superseded chain is dropped; flush applies; a namer miss
  falls back. UI: dragging a sketch point under an extrude keeps the canvas responsive and,
  after mouse up, the solid equals a full synchronous regenerate.
