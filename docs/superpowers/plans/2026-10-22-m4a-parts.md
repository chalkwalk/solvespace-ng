# M4a Parts in One File Implementation Plan

> **For agentic workers:** superpowers:executing-plans, inline. On 2026-10-21 the owner said
> "go with whatever you think is the best ROI"; M3's "done when" is met, so M4 is next in
> milestone order (AGENTS.md section 8).

**Goal:** M4's "done when": an enclosure and lid co-designed in one file export two
printable parts. This plan covers parts, cross-part references, every part shown and
pickable, and export per part (STL and STEP). Placement constraints and the design pose,
3MF, the BOM and `LINKED` compatibility follow in M4b.

**Architecture (AGENTS.md section 7, kept as small as the model allows):**
- **A part is a tag on groups.**
  - `Group::part` (hPart, saved `Group.part.v`; 0 is the first part, so old files are
    unchanged).
  - The part list is `SK.part`, with a name per part (records `AddPart`, `Part.h.v`,
    `Part.name`), written only once a file has a second part.
  - The global group order stays, as the dependency order.
- **Each part has its own solid.** A group's running solid continues from the previous
  group of the same part (`Group::RunningMeshGroup`, `Sketch::GetRunningMeshGroupFor`), so
  a part's extrusions never merge into another part's. The worker chain already links jobs
  by their previous group, so it follows.
- **Cross-part references come free.** A group may use any entity of an earlier group
  (constraints, workplanes, sketching on a face), whatever its part, as today. That is the
  co-design tool: the lid is sketched on the enclosure's rim. The skeleton is simply sketches
  any part uses.
- **Display and picking.**
  - The viewport shows each part's solid as of the active group: the active group's, and
    for every other part, its latest group before it.
  - Faces of any shown part can be picked, the active part first.
- **Commands and panels.**
  - New Part (`part-new`; New Group menu) makes the next part and a 3D sketch group in it.
    New groups join the active group's part.
  - The Outliner heads each part's groups with the part's name once there are two parts.
    Properties of a group shows its part, and renames it.
- **Export.** Export ▸ Parts (`export-parts`) writes one file per part:
  `<name>-<part>.stl` or `.step` (the OCCT B-rep). Its core is
  `SolveSpaceUI::ExportParts(path)`, which is testable.

## Global constraints
As before. Old files open and save byte-identical (golden tests). Parts must not slow the
single-part case.

## Review focus
1. A single-part file behaves exactly as before: same solids, same saved bytes.
2. A difference group in part B never cuts part A.
3. Deleting a part's last group: the part stays listed (empty) and exports nothing.
4. Undo across creating a part.
5. Linked groups and step-and-repeat inside the second part.
